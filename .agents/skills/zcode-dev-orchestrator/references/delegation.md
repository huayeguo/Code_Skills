# 代理任务约定与机队路由

仅在决定实际分工或需要配置机队时读取。任务大小不等于推理难度；角色名不保证专业能力。

## 任务约定

每个代理收到最小充分背景和以下信息。已有明确事实通过路径与符号引用，避免复制整个旧对话。

```text
子任务：具体问题或交付结果
目的：它如何服务当前验收标准
已知事实：来源路径、符号或证据
工作位置与基线：实际目录、分支/提交、必要的未提交差异
读写边界：优先读取路径；只读或允许修改路径
依赖与接口：等待哪些决定，必须遵守哪些约束
不确定项：尚未证实且影响工作的假设
交付：结论/变更、证据、检查结果、残留问题
停止条件：满足验收；发现越界/接口冲突时返回主代理
执行配置：实际派发的子代理类型及其卡片固化档位
```

独立 worktree 不自动含有主工作区的未提交文件，派发前确认所需基线确实存在。共享工作区中不要并行修改同一文件。全局 STATE 和公共接口由指定负责人维护。

审查者返回可定位的问题与证据，不只给“通过/不通过”。主代理核实是否需要修改；有分歧时以原始证据和验收标准解决，不按代理票数决定。

## 并行度与批次

不要把“通常两个代理”当成固定容量，也不要因为任务大就一次启动尽可能多的代理。先建立任务图，并对每个候选子任务标明：独立产出、依赖项、读写所有权、预期中间材料和是否会解除其他任务的阻塞。

每一批可启动数量取以下三项中的最小值：

1. 当前已就绪且互不依赖的子任务数量；
2. 调用工具当前剩余的并发槽位；
3. 主代理能在该批返回后可靠审查和整合的结果数量。

如果独立任务多于并发槽位，先启动最能减少不确定性或解除依赖的任务，结果返回后重新计算下一批。大型项目可以有多个批次和多个代理；并行数量由任务结构和运行时容量决定，不要求用户预先指定代理数量。

以下情况必须串行：共享接口尚未确定；同一文件或数据迁移需要写入；后续任务依赖前一项结论；或并行结果会造成不可控的重复探索。只读任务也不天然适合并行：单一状态汇报通常由主代理直接完成，广泛架构审阅可以按独立领域拆成多批调查。

## 机队路由

用户或项目已明确指定执行者或模型时，保留该选择。否则，主代理按子任务性质路由：

| 子任务性质 | 初始路由 |
|---|---|
| 确定性搜索、格式转换、明确事实提取 | 先直接使用工具；必要时 `orch-scout` |
| 项目状态核实、代码地图、文档梳理 | `orch-scout`，可按批次并行 |
| 已有模式的实现、明确失败用例对应的局部调试 | `orch-builder` |
| 模糊根因、跨模块取舍、高代价迁移或独立审查 | `orch-auditor`，或主代理直接处理 |
| 已有具体未解决难点，且更深推理有明确价值 | 主代理直接处理，必要时 `orch-auditor` |

权限、并发或跨模块语义调查不是纯提取任务，不应因“只是阅读文件”而降级。一次普通测试失败也不自动升级执行档；先补证据与假设。

派发消息必须自包含最小充分背景：ZCode 子代理不继承主对话历史。需要追加追问时用 SendMessage 恢复原子代理，不重新派发。派发前确认目标类型在当前会话可用；机队成员不可用时改用内置 `Explore` 或 `general-purpose`，并在派发记录中注明。

## 机队规格与重建

机队是固定的小集合，放在 `~/.zcode/agents/`；项目专属角色放 `<仓库>/.zcode/agents/`，随版本库共享。ZCode 在会话启动时扫描名单，会话中新建的卡片下个会话生效。缺失时按下表重建，当前会话改用内置类型，不为等待铸造而阻塞已授权任务。

| 卡片 | 职责 | 档位 | 工具 |
|---|---|---|---|
| `orch-scout` | 只读调查、状态核实、代码地图 | `model: GLM-5.3-Flash` | Read, Bash |
| `orch-builder` | 限定范围内的实现 | 不写字段，继承会话模型 | 全部工具 |
| `orch-auditor` | 独立证据审查 | `model: GLM-5.3` | Read, Bash |

角色按档位划分，不按业务领域划分；项目特异性由派发消息承载，不因单个项目新造卡片。

成本控制首先靠限定问题、减少无关上下文、避免重复探索和明确停止条件；不用“固定派给最轻一档”替代风险判断。
