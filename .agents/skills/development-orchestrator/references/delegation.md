# 代理任务约定与模型选择

仅在决定实际分工或需要配置覆盖时读取。任务大小不等于推理难度；角色名不保证专业能力。

## 任务约定

每个代理收到最小充分背景和以下信息。已有明确事实通过路径与符号引用，避免复制整个旧对话。

```text
子任务：具体问题或交付结果
目的：它如何服务当前验收标准
已知事实：来源路径、符号或证据
工作位置与基线：实际目录、分支/提交、必要的未提交差异
读写边界：优先读取路径；只读或允许修改路径
依赖与接口：等待哪些决定，必须遵守哪些约束
不确定项：尚未证实且影响工作的假设
交付：结论/变更、证据、检查结果、残留问题
停止条件：满足验收；发现越界/接口冲突时返回主代理
执行配置：实际传入的模型与推理等级；继承时写明触发继承的原因和父代理实际配置
```

独立 worktree 不自动含有主工作区的未提交文件，派发前确认所需基线确实存在。共享工作区中不要并行修改同一文件。全局 STATE 和公共接口由指定负责人维护。

审查者返回可定位的问题与证据，不只给“通过/不通过”。主代理核实是否需要修改；有分歧时以原始证据和验收标准解决，不按代理票数决定。

## 模型与推理选择

用户或项目已明确指定模型或推理等级时，保留该选择。否则，主代理必须为每个子代理动态选择并在实际启动调用中显式传入模型和推理等级；不省略字段让其自动继承父代理。

启动前按以下顺序判断：

1. 列出当前调用工具实际支持的模型与推理等级。工具给出的可用选项优先于本文件的名称示例。
2. 判断该子任务是确定性提取、常规工程、复杂推理、还是高代价独立审查；同时考虑可逆性、耦合、证据完整性和验收难度。
3. 选择足以完成任务的最低能力档与推理等级，并写出一行理由。
4. 在实际启动调用中同时传入 `model` 与 `reasoning_effort`；然后确认启动记录显示的不是空值或继承值。在支持 `fork_turns` 的 Codex 分派工具中，显式覆盖不与 `fork_turns: "all"` 同用；改用 `"none"` 或正数的最近轮次，并在任务消息中提供最小充分背景。

| 子任务性质 | 初始路由方向 | 推理方向 |
|---|---|---|
| 确定性搜索、格式转换、明确事实提取 | 先直接使用工具；必要时选择当前可用的轻量档 | low |
| 项目状态核实、代码地图、文档梳理 | 当前可用的轻量或平衡档 | low 或 medium |
| 已有模式的实现、明确失败用例对应的局部调试 | 当前可用的平衡编码档 | medium |
| 模糊根因、跨模块取舍、高代价迁移或独立审查 | 当前可用的强能力档 | high |
| 已有具体未解决难点，且更深推理有明确价值 | 当前可用的最强适配档 | xhigh、max 或 ultra，仅在支持时 |

权限、并发或跨模块语义调查不是纯提取任务，不应因“只是阅读文件”自动降为 low。一次普通测试失败也不自动提高模型或推理；先补证据与假设。

候选模型或等级不可用时，先从工具支持列表选择另一个可显式传入的配置。只有工具不支持单个子代理覆盖、没有任何可显式传入的支持配置，或用户明确要求继承，才可继承父代理。必须在派发说明和最终报告中写明：`继承原因 → 父代理实际模型/推理等级`。不能因未配置 `[agents]` 默认值而继承，也不能声称已经选择了没有传入启动调用的配置。

全局 `[agents]` 的默认模型和推理等级只是兜底，不提供按任务动态分流。固定角色需要稳定配置时，可使用当前客户端支持的自定义 agent 文件；动态任务仍由本流程在启动时显式覆盖。

成本控制首先靠限定问题、减少无关上下文、避免重复探索和明确停止条件；不用“便宜模型处理所有调查”替代风险判断。
