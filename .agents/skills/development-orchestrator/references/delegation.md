# 代理任务约定与模型选择

仅在决定实际分工或需要配置覆盖时读取。任务大小不等于推理难度；角色名不保证专业能力。

## 任务约定

每个代理收到最小充分背景和以下信息。已有明确事实通过路径与符号引用，避免复制整个旧对话。

```text
子任务：具体问题或交付结果
目的：它如何服务当前验收标准
已知事实：来源路径、符号或证据
工作位置与基线：实际目录、分支/提交、必要的未提交差异
读写边界：优先读取路径；只读或允许修改路径
依赖与接口：等待哪些决定，必须遵守哪些约束
不确定项：尚未证实且影响工作的假设
交付：结论/变更、证据、检查结果、残留问题
停止条件：满足验收；发现越界/接口冲突时返回主代理
执行配置：实际使用的模型与推理等级；继承时写继承
```

独立 worktree 不自动含有主工作区的未提交文件，派发前确认所需基线确实存在。共享工作区中不要并行修改同一文件。全局 STATE 和公共接口由指定负责人维护。

审查者返回可定位的问题与证据，不只给“通过/不通过”。主代理核实是否需要修改；有分歧时以原始证据和验收标准解决，不按代理票数决定。

## 模型与推理选择

在用户或项目已经指定模型时，保留其选择。工具能列出的可用模型和支持的推理等级优先于旧文档中的路由表。能力档位只是起点，应通过真实任务效果调整。

| 子任务性质 | 初始选择 | 注意事项 |
|---|---|---|
| 确定性搜索、格式转换、提取明确信息 | 首先直接用工具；需要代理时使用可用轻量档和 low | 需要判断权限、并发或跨模块语义时不属于纯提取 |
| 已有模式的实现、明确失败用例对应的局部调试 | 项目默认或平衡档；medium 若受支持 | 不因文件多就自动提高推理 |
| 模糊根因、跨模块取舍、高代价迁移或独立审查 | 可用强能力档；high 若受支持 | 先补事实与验收标准，不用推理额度弥补缺失信息 |
| 已有具体未解决难点且深推理可能有效 | 在支持时进一步提高 | 不因一次普通测试失败就升级模型或推理 |

用户以及适用的全局/项目指令均没有明确要求自动选型时，默认继承父代理。若用户或适用指令采用本技能的自动选型策略，可在受支持范围内按以上表选择子代理模型和推理；无需为每次常规路由再次提问。无法验证映射或工具不能覆盖时继承并说明。主代理自身是否能切换模型由客户端能力决定，不通过文字宣称切换。

成本控制首先靠限定问题、减少无关上下文、避免重复探索和明确停止条件；不用“便宜模型处理所有调查”替代风险判断。
